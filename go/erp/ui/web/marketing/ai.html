AI & Security

An AI agent built for business data, so sensitive values never leak to the model.

Tanto (Layer8) is the AI agent in ERP by Layer 8. It lives in the built-in team chat, answers questions with live queries against your ERP, and can create and update records when you ask. Every design decision starts from one rule: the language model gets the least it needs to reason, and nothing it could leak.

How a question is answered

Your data goes out as tokens and comes back as answers.

  1. You ask in the chat. For example: "What is the average base salary in Engineering, and who is the highest paid?" Social security numbers, money amounts, emails and phone numbers in your message are tokenized before the model sees it.
  2. The model plans a query. It knows the ERP's models and services, not your records. A query that would pull an unbounded list is rejected; totals must use aggregates.
  3. The query runs as you. Tanto executes it with your identity, so it sees exactly the rows and fields you are allowed to see. There is no AI service account that bypasses permissions.
  4. Sensitive fields become tokens. Every field marked sensitive in the data model, and every aggregate over it, is replaced with a stable token like [MASK_7QX2KD] before the result goes to the model. The same value always gets the same token in a conversation, so the model can still compare and group.
  5. The answer is restored for you. The tokens in the model's reply are swapped back to the real values only in the message shown to you. The model provider never receives them.

What is masked

237 sensitive fields in the ERP data model are masked from the AI.

Sensitivity is declared in the data model with one annotation, [(l8ai.AIMask) = true], and enforced from the compiled schema at run time. Nothing is guessed from field names, so the agent never hides a value it needs and never sends one it should not. An automated test fails if a known sensitive field loses its annotation.

Names & dates of birth National IDs & SSNs Emails, phones & addresses Bank account & routing numbers Salaries & payroll totals Equity grants Performance ratings & reviews Signatures IP addresses & sessions Connection strings & credentials

Security model

More than masking.

Identity

The agent is not a user

Tanto has no login, password or role, so there are no AI credentials to steal. Its replies are accepted only from verified agent instances for the current turn, and no browser token can post as Tanto.

Authorization

Your permissions, every call

Each tool call carries the requester's identity, so row scope and deny rules apply. When the session ends, the turn ends with a message asking you to sign in again. It never falls back to another identity.

Context hygiene

Tool results are not replayed

Raw query results are never carried from turn to turn; only the assistant's final text is kept. Long conversations are summarized, and the summaries are masked like everything else.

Model choice

Hosted or on-premise LLMs

LLM providers and profiles are managed centrally in the security service, together with their API keys. Use Anthropic or any OpenAI-compatible endpoint, including models on your own servers, and pick the profile per conversation.

Scale

A chat built to scale

The chat and the agent are separate services: a router, in-memory chat instances, a transactional chat database, presence and groups, and horizontally scaled agent instances. It is designed for 20,000 users.

Live

Real-time by default

Messages, conversations and presence arrive over websockets in order, with automatic gap filling after a reconnect. The same chat runs on desktop and mobile, with groups, file sharing and Markdown answers you can copy.
